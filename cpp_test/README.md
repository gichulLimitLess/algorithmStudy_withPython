# C++ 코딩테스트 작업 폴더

## 문제 풀이 흐름

1. `template.cpp`를 복사해서 `문제풀이/BOJ_1234_문제이름.cpp` 로 만든다.
2. 같은 폴더에 `input.txt`를 만들고 문제의 예제 입력을 붙여넣는다.
3. 풀이 파일을 연 상태에서 **`Cmd+Shift+B`** → 빌드 후 바로 실행된다.
4. 통과하면 파일 내용을 그대로 복사해서 제출한다.

> `input.txt`는 **풀이 파일과 같은 폴더**에 있어야 한다. (실행 위치가 그 파일 폴더 기준)

## 빌드 태스크 (`Cmd+Shift+P` → `Tasks: Run Task`)

| 태스크 | 용도 |
|---|---|
| **C++: 빌드+실행** | 기본. `Cmd+Shift+B` 단축키에 연결됨 |
| **C++: 빌드+실행 (-O2 시간측정)** | 채점 서버와 같은 `-O2`. 시간초과 판단용 |
| **C++: 빌드+실행 (Sanitizer)** | 런타임 에러(배열 범위 초과, 오버플로우) 위치를 줄 번호로 알려줌 |
| **C: 빌드+실행** | 순수 C 파일(.c) 전용 |

## 디버깅

`F5` → CodeLLDB로 중단점 디버깅. 입력은 마찬가지로 `input.txt`에서 읽는다.

## `#include <bits/stdc++.h>`

GCC 전용 헤더라 macOS clang에는 없어서, `include/bits/stdc++.h`에 대체본을 두고
빌드 시 `-I include`로 잡아준다. 백준 제출 코드를 수정 없이 로컬에서 돌리기 위한 것.

## `#ifdef LOCAL` 블록

```cpp
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif
```

로컬 빌드에만 `-DLOCAL`이 붙으므로 이 블록이 살아나 `input.txt`를 읽는다.
채점 서버에는 `LOCAL`이 없어서 블록이 통째로 사라지고 정상적으로 표준입력을 읽는다.
**따라서 이 코드를 지우지 않고 그대로 제출해도 된다.**

## 컴파일 환경

- Apple clang / `-std=gnu++17` (백준·프로그래머스·코드트리 모두 호환)
- 빌드 산출물은 `.bin/`에 생성되며 git에서 제외된다
